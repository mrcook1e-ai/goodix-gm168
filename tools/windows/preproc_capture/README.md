# GM168 Wbdi preprocessor full-trace capture

Захват эталонных выходов Windows-драйвера (`Wbdi.dll`) на каждом этапе
обработки изображения. Делается **один раз** на твоей машине. Полученные
дампы потом byte-сравниваются с выходами нашего Linux-драйвера — точно
находим где наша реализация расходится с Windows.

## Что внутри

- `capture.bat` — главный launcher. Сам ставит Frida, находит процесс
  с `Wbdi.dll`, делает все хуки, складывает дампы в `captures/<timestamp>/`.
- `gx_preproc_trace.js` — Frida-скрипт с 11 хуками на функции `Wbdi.dll`
  (CAL, SMOOTH, HENV, VENV, MORPH, STRETCH и т.д.). Каждый вызов
  сохраняется как `.bin` файл с числовым ID для парного сравнения
  `IN`→`OUT`.

## Что нужно

- Windows 10/11 на ноуте где сенсор GM168 (тот же сенсор что в Linux)
- Доступ админа (`Run as administrator`)
- Python 3.10+ (если нет — скачай с [python.org](https://www.python.org/downloads/), при установке поставь галку "Add Python to PATH")
- Интернет (только для `pip install frida-tools` первый раз)

## Шаги

1. **Скопируй эту папку** (`preproc_capture/`) целиком на Windows. Куда угодно — например, на рабочий стол.

2. **Правый клик** на `capture.bat` → **Run as administrator**.
   - Скрипт сам поставит `frida` если не установлен (~30 секунд первый раз).
   - Если попросит UAC — соглашайся.

3. **Когда увидишь** `Open Settings - Sign-in - Fingerprint`:
   - Открой `Параметры` → `Учётные записи` → `Параметры входа` → `Распознавание отпечатков`
   - Это разбудит `Windows Biometric Service` и она загрузит `Wbdi.dll` в `WUDFHost.exe`.
   - Скрипт сам найдёт нужный процесс (ждёт до 2 минут).

4. **Когда увидишь** `HOOKS_READY (11 callees)`:
   - **Один раз** приложи палец к сенсору. Обычное касание — как при входе.
   - **Подожди 3 секунды** — за это время Wbdi пройдёт весь pipeline и хуки
     запишут все промежуточные буферы.
   - **Нажми Ctrl+C** в окне команды чтобы остановить захват.

5. **Дампы сохранятся** в `captures/YYYYMMDD-HHMMSS/`. Должно быть несколько
   сотен .bin файлов разных стадий — скрипт распечатает сколько на каждом
   этапе. Если строчек `INPUT: 1+ files`, `CAL_OUT: 1+ files`, `STRETCH_OUT: 1+ files` —
   захват успешен.

6. **Скопируй** папку `captures/` на Linux-ноут:
   - На Linux должно быть в `~/work/goodix-gm168/captures/`
   - Можно через USB-флешку, SCP, или просто перезагрузиться в Linux и
     взять с локального NTFS-раздела.

## Что дальше

После того как дампы окажутся на Linux:

```bash
ssh mrcook1e@192.168.1.23
cd ~/work/goodix-gm168
# (capture folder уже скопирована сюда)
python3 scripts/compare_wbdi_dumps.py captures/<timestamp>/
```

Скрипт byte-сравнения покажет:
- На каких этапах наш driver совпадает с Wbdi
- На каком первом этапе расходится → это и есть бага

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `Python not installed` | Скачай с python.org, при установке отметь "Add to PATH" |
| `TIMEOUT: WUDFHost never loaded Wbdi.dll` | Открой Settings → Sign-in → Fingerprint. Если уже открыто — попробуй sign out / sign in. |
| `ERROR: Wbdi.dll not found` (от Frida) | Скрипт нашёл WUDFHost, но не тот — есть несколько процессов с этим именем. Сейчас бат берёт первый. Подожди пока settings закроется и попробуй ещё раз. |
| `pip install failed` | Запусти вручную: `py -m pip install frida frida-tools` |
| Палец приложил, но дампы пустые | Возможно драйвер засыпает — приложи палец ещё раз пока окно команды активно |

## Безопасность

Скрипт:
- Запускается **только локально** (никаких сетевых соединений кроме pip install)
- Читает память **только** процесса `WUDFHost.exe` (где `Wbdi.dll`)
- Пишет дампы **только** в `C:\Windows\Temp\gx_dumps\` и в свою папку
- Никаких изменений в системе/драйверах/реестре
- `frida` — известный open-source инструмент для динамического анализа
